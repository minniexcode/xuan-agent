# 玄枢（xuan-agent）架构决策记录（ADR）

记录难以逆转、且需要向后来者交代"为什么"的决策。每条一段话讲清背景、决策与理由；按顺序编号。

## ADR-0001：TypeScript-first + 单 npm 包

- 状态：已采纳（2026-10-15）

V1 以 TypeScript（Node.js）为主栈，交付单个 npm 包 `xuan-agent`，同时承载 CLI（`xuan`）与 SDK。原因是 CLI、SDK、类型声明、npm 分发与后续 Web/IDE 集成都更契合 TS 生态，且单包可同时服务命令行与可复用 SDK，避免早期引入 monorepo 复杂度。Python 不进入 V1 依赖，仅在 `tyme4ts` 精度不足时作为 `BaziCalculator` 的后备 adapter。

## ADR-0002：计算与解读分离

- 状态：已采纳（2026-10-15）

排盘、历法换算、干支推导、十神映射、大运流年等确定性计算全部交给库（`tyme4ts`，经 `BaziCalculator`），LLM 只做解释、总结、引用与追问。原因是 LLM 直接排盘错误率极高，会让产品失去准确性根基；分离后计算可复现、可测试，幻觉被隔离在解读层。排盘失败时返回明确错误，不得让 LLM 补算。

## ADR-0003：排盘库 `tyme4ts`，经 `BaziCalculator` 隔离

- 状态：已采纳（2026-10-15，2026-10 换库）

八字计算用 `tyme4ts`，但业务层只依赖 `BaziCalculator` 接口返回的 `BaziChart`，不得直接使用第三方库对象。原因是排盘库的精度与 API 都可能变化，隔离后换库或补规则不影响 CLI、SDK、Skill 与解读链路。

选型经过一次三实现交叉对拍（`tyme4ts` / `lunar-typescript` / `cnlunar`，21 例）：`tyme4ts` 与 `lunar-typescript` 结果一致、节气时刻与权威值逐秒吻合；`cnlunar` 有误被排除。最终选 `tyme4ts` 因其为作者新一代实现、节气采用寿星天文历算法、API 更规整；隔离层保证这个选择随时可换。

## ADR-0004：插件化 Skills 架构

- 状态：已采纳（2026-10-15）

每个能力模块作为独立 Skill，经 `SkillRegistry` 注册，统一声明输入、输出、依赖能力与安全边界。原因是五术门类多，若各能力耦合进核心 Agent，每新增一门都要改造核心；Skill 化后新增相术、六爻、紫微等只需新建目录并注册，复用统一的记忆、Provider、RAG 与 Safety。

## ADR-0005：LangGraph.js 编排 + LangChain.js 抽象

- 状态：已采纳（2026-10-15）

Agent 编排用 LangGraph.js 表达有状态流程（八字、追问、对比）并用 checkpointer 保存会话；LLM 抽象用 LangChain.js 统一 Provider 调用与 streaming，经 `ProviderFactory` 隔离。原因是自研有状态编排与多 Provider 抽象成本高，而追问与同盘复用需要可靠的状态管理。

## ADR-0006：V1 单 Provider，多 Provider 对比延后

- 状态：已采纳（2026-10-15）

V1 默认单一 Provider——DeepSeek，经 `openai-compatible` adapter 接入（`anthropic` 保留骨架）；多 Provider 对比降级为 V1 完成后能力，且不做自动评分。原因是个人验证阶段实际主要用 DeepSeek key，若只有一个 key，"对比"会空转，而对比维度打分成本高。Provider 抽象保持可切换，后续接入新模型不改业务逻辑。

## ADR-0007：V1 聚焦八字，相术推迟 V2

- 状态：已采纳（2026-10-15）

V1 只做八字，相术（面相/手相）整体移入 V2。原因是玄枢的核心假设是"计算与解读分离"，八字直接检验它；相术是纯 Vision LLM、无确定性计算，做它不验证核心假设，却带来最大的隐私与安全成本（真实人脸 + 外部 Provider + 身份识别红线）。

## ADR-0008：本地优先存储 + 隐私默认

- 状态：已采纳（2026-10-15）

存储本地优先：档案用本地 JSON、会话用本地 checkpoint；默认不持久化出生信息、出生地、图片与完整对话，写档案须用户显式确认；日志脱敏，不记录完整 API key、出生信息、图片内容与未脱敏档案。原因是这些数据都属敏感个人数据，默认安全比事后免责更可靠。

## ADR-0009：中性分析安全边界

- 状态：已采纳（2026-10-15）

输出坚持中性、非断言：用"倾向""观察角度"等表达，避免"必然""注定""大凶"；用户索要吉凶时由 `SafetyGuard` 降级——承认诉求、说明能力边界、转为可观察的结构或倾向、不给是/否结论。原因是确定性断言有误导与合规风险，而玄枢的定位是克制、可追溯的自我探索工具；该规则进入系统逻辑与 Prompt，而非仅靠文档提醒。

## ADR-0010：晚子时日柱默认"次日"（23:00 换日）

- 状态：已采纳（2026-10-15）

23:00–23:59 出生的日柱，V1 默认按**次日**计算。此选择反直觉：古典**历法**传统（《革象新书》《蠡海集》《清史稿》）主张"子正换日"即 00:00 换日；但**术数排盘的通行实践**是 23:00 换日，且经核实，问真、元亨利贞、易运盘、问道八字、卜易居**全部默认次日**（问真系由其线上接口验证），`tyme4ts` 默认亦为次日。

选"次日"是为对齐生态、零偏离所选库。但流派确有分歧，故做成可切换（`LunarHour.provider`），并要求凡出生时间落在 23:00–23:59 时在 `limitations` 中标注所用流派——**不允许静默选边**。
