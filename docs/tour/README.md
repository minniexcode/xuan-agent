# 玄枢代码导览（渐进式阅读指南）

面向"要 review 代码"的读者。按**从外到内、从整体到细节**的顺序组织：先看全貌和依赖，再逐层读代码。

配套文档：产品意图看 [`../prd.md`](../prd.md) / [`../requirements.md`](../requirements.md)，设计契约看 [`../technical-design.md`](../technical-design.md)，决策理由看 [`../adr.md`](../adr.md)。**本导览只讲"代码现在长什么样、为什么这么长"**，不重复产品需求。

---

## 怎么用

### 阅读路线

| 路线 | 读什么 | 耗时 |
| --- | --- | --- |
| **速览** | [01-全局](01-全局.md)，**尤其其中的实跑快照** | ~20 分钟 |
| **完整 review** | 01 → 02 → 03 → 04 → 05 顺序读 | ~1.5 小时 |
| **只为 Vision 做准备** | [01-全局](01-全局.md) 的实跑快照 + [02-基础层](02-基础层.md) 的计算/Provider + [06-Vision 接入点](06-Vision接入点.md) | ~40 分钟 |

### 建议的读法

这份导览是**地图**——它告诉你每块代码在哪、为什么这么写、读的时候注意什么，并把最容易踩的坑和规格差距挑出来。但它不能替代读源码。建议顺序：

1. **先读 [01-全局](01-全局.md) 里的实跑快照**（20 分钟）—— 建立数据直觉
2. **按 02 → 05 逐层读代码**（每份对照源码看，约 1 小时）
3. **最后看 [05 的检查清单](05-测试与Review.md#review-检查清单)**做判断

## 维护约定

**逐层文档（01–06）永远反映最新代码**，不保留旧版本内容 —— 新读者只看这几份就够，不必判断"哪份是最新的"。

**版本演进记录在 [07-版本变更](07-版本变更.md)**：每次迭代追加一节，写清「新增了什么 / 改动了哪些文件 / 为什么」。

具体做法：

1. 逐层文档**原地更新**到最新；V2 新增的段落加一句 `> 🆕 V2 新增` 标注，方便老读者定位变化。
2. [07-版本变更](07-版本变更.md) 追加一节（版本号、日期、新增、改动、原因、影响文件）。
3. 版本地图（上面那张表）更新状态。
4. 若某次迭代引入**新的代码层**（如 V2 的 `src/skills/`），在 01 的目录表与对应逐层文档里补上。

> 不做"每版一套完整文档"—— 那会要求把 V1 的内容在 V2 里重写一遍，维护成本翻倍且极易不同步。
