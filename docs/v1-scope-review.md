## 1. 本次采用的范围与判定原则

依据 [PRD](prd.md)、[详细需求](requirements.md)、[产品架构](product-architecture.md)、[技术设计](technical-design.md) 及已采纳的 [ADR](adr.md) 核对。对于被明确取代的旧约定，以新的 ADR 为准；旧段落仍有残留时记为文档同步项，不重新要求实现已延期的功能。

本轮范围变更已形成正式记录：

- **ADR-0012**：V1 为个人 CLI 的 happy path 排盘、解读、同盘追问；sections 已实现。节气、最近 10 年流年、大运步数/流年范围参数、SkillRegistry、CLI 交互补全、`--new` / `--provider` / `--model` / `--save-profile`、档案回填、晚子时流派切换入口均移 V2。
- ADR-0012 明确取代 ADR-0004 对 V1 的 Skill 注册义务，移除 `both`，最低 Node 版本调整为 `>=22.12`。
- ADR-0012 澄清 ADR-0008：会话含盘面输入，自动本地保存、可清理、不自动过期；长期档案另需显式确认。原隐私范围冲突已在决策层关闭。
- ADR-0011 已取代旧 LangChain / LangGraph 方案。当前自研 Provider 和线性编排符合决策，不要求补回旧框架。

继续保留用户已明确的边界：

- **安全结果**：CLI/SDK 返回原文、`safety.blocked` 和 warnings；未来面向用户的服务自行决定处置。命中后返回 `blocked:true` 合理，不要求 SDK 隐藏、改写或停止返回原文。
- **知识内容**：seed 与计算库输出的差异不等于已经证明 seed 错误。R02 保留为待核对差异，不计功能缺陷、不改内容。
- **同盘追问**：现有冻结盘面的追问能力已被认可。不要求增加历史回答存储或完整多轮对话；前轮发现的输出解析问题已修复，不改变该能力边界。

文档先行的本轮结论是：**范围裁剪已有 ADR 依据，晚子时切换的延期也已补入 ADR-0010/0012；both、进阶流年指令、架构主要旧表述、导览的过去时描述均已修正。其余旧示例列于 §4，不重新要求实现已延期功能。**

## 3. R04 的两个 P2 输出回归：均已关闭

### R04-A：追问标题与建议区正文保留，已关闭

[`section-parser.ts:37`](../src/prompts/section-parser.ts#L37) 现在只将精确标题“可继续追问”作为问题列表；其他标题正常进入 sections。该标题内的非列表正文也单独保留，因此无列表或正文/列表混合时都不会丢弃说明。

本轮验证：

- `## 追问解答` 加正常正文 → 普通 section；经构建后 SDK 的 askFollowup 返回及文本 renderer 验证，回答可见。
- `## 可继续追问` 加非列表正文 → 正文保留为 section，followupQuestions 为空。
- “可继续追问”下同时有正文和 bullet → 正文保留在 section，问题提取到 followupQuestions。

两个新增解析器单测及独立行为探针通过，不再保留该 P2。

### R04-B：摘要与 sections 独立渲染，已关闭

[`bazi-renderer.ts:50`](../src/cli/renderers/bazi-renderer.ts#L50) 现在先渲染非空 summary，再渲染全部 sections；二者皆空才显示占位“（空）”。

新增 `renderer.test.ts` 覆盖摘要与章节共存、仅摘要、两者皆空三种行为。独立探针另验证“总览标记A”和“正文标记B”同时存在、摘要在前，正文存在时不出现空占位。

**当前没有未关闭的 P0/P1/P2 代码发现。** 本结论针对本轮复核范围，不代表已穷尽所有输入组合或完成真实模型质量验收。

## 5. 可后续处理的低优先级余项（P3）

### R09：content 类型问题已关闭，仅响应根值 null 仍保留

位置：[`openai-compatible.adapter.ts:106`](../src/providers/openai-compatible.adapter.ts#L106) 起的 JSON 解析及内容读取。

已独立用 fetch 替身验证，无网络请求：

| HTTP 200 响应正文 | 实际结果 |
| --- | --- |
| 非 JSON 文本 | XuanError / LLM_ERROR，原问题已修复。 |
| `{}` | XuanError / LLM_ERROR，空回答已拒绝。 |
| `{"choices":[{"message":{"content":null}}]}` | XuanError / LLM_ERROR；content 为 null 已能按空回答处理。 |
| `{"choices":[{"message":{"content":123}}]}` 或 content 为 object | XuanError / LLM_ERROR；本轮新增类型防御已生效。 |
| 整个正文为 `null` | 仍为原生 TypeError，无 code；读取 data.choices 时失败。 |
| 合法非空 string content | 正常成功。 |

`content:null` 与整个响应 JSON 为 `null` 是两个不同输入。前轮报告表格中的 null 指后者；本轮非字符串 content 的问题已关闭，不能继续记为未修复。

剩余问题仅为整个响应根值为 null 的异常协议边界，不阻断正常 Provider 回答，仍列 P3。后续可在访问 data.choices 前校验根对象，或将该协议读取过程统一包装为 LLM_ERROR；本轮不修改业务代码。

### R12：无命中说明与引用文本展示尚未全部对齐

- **已关闭的部分**：术语门控已实现，“说人话”不调用 search 的断言已通过，不再报告每轮追问无条件检索。
- **无命中说明**：FR-RAG-02 规则 1 仍要求明确告知无可靠依据。`buildBaziPrompt` 仅在 citations 非空时插入依据段；独立注入空知识库做 advanced analyze，citations 为 []，Prompt 与 CLI 输出均无固定的未命中说明。说明仍可能由模型自行生成，但实现没有保证。独立 `rag search` 的空结果 renderer 已有说明，follow-up Prompt 也已有回退说明，不能笼统说全部缺失。
- **引用展示**：SDK/JSON 已分别提供 excerpt、interpretation、summary；分析文本只打印来源/摘录，rag search 文本没有打印 summary，尚未完整呈现 FR-RAG-02 的三类内容区分。
- **通俗来源策略**：当前 beginner 分析跳过检索，而规则 2 仍写“通俗模式只给简短来源”；先统一保留的需求与实际策略，不强行扩成复杂检索系统。

这些是原 R12 尚未关闭的提示/展示条款，不表示检索管线或同盘追问不可用。
